### 2.3 — Session 2026-05-05 Vague 1 : Auth parité (4 P1 fermés)

**Commits** : backend `1d43a60` (21 files, +1698/−72) ; mobile `9eeba20` (5 files, +246/−26) ; web `7d5082b` (15 files, +967/−188).

#### 2.3.1 Login unifié
- **Endpoint canonique** : `POST /api/v1/auth/login` JSON body unique. Réponse : `{ accessToken, refreshToken, user, requires2FA?: boolean, tempToken?: string }`. **Plus de cookies serveur** — chaque client pose ses propres cookies/SecureStore.
- Anciens chemins `/auth/login`, `/mobile/auth/login` deviennent **alias** du même handler (rétro-compat). Les vraiment legacy isolés derrière `/*-legacy` pour rollback éventuel.
- **Mobile** : `services/api/auth.ts` migré sur `/v1/auth/login`. `requires2FA` lu avec fallback `requiresTwoFactor`. User du nouveau contrat utilisé direct (évite round-trip `/users/:id`).
- **Web** : `api/auth.ts` migré ; cookies httpOnly posés via nouvelle route Next.js `app/api/auth/set-cookies/route.ts` avec validation JWT shape (`__Host-token`/`__Host-refreshToken` en prod, `sameSite=lax`). Route `/api/auth/clear-cookies/route.ts` au logout.

#### 2.3.2 2FA unifié
- **Endpoint canonique** : `POST /api/v1/auth/complete-2fa` body `{ tempToken, code }` → `{ accessToken, refreshToken, user }`. Le tempToken accepte les **deux formats** (legacy `type: "temp-2fa-web"` + nouveau `purpose: "2fa_verification"`) pour migration souple.
- Anciens `/auth/complete-2fa-login` et `/mobile/2fa/verify-login` = alias.
- Mobile + web migrés.

#### 2.3.3 Codes 403 distincts (UNAUTHORIZED/BLOCKED/UNVERIFIED/PENDING_VALIDATION)
- **Helper backend** : `src/utils/authErrors.ts` `sendForbidden(code, message, details)` produit le shape unifié partout.
- **Shape** : `{ error: "FORBIDDEN", code: "BLOCKED"|"UNVERIFIED"|"PENDING_VALIDATION"|"UNAUTHORIZED", message, details? }`
- Appliqué sur `adminMiddleware`, `authMiddleware`, `mobileAuthMiddleware`, `maintenanceMiddleware`, `unifiedAuthController`. Les controllers legacy `handleLoginUser`/`handleMobileLogin` gardent les anciens flags (`accountBlocked`, `emailNotVerified`) en plus du nouveau shape pour ne casser personne.
- **Mobile** : `ForbiddenError` typée dans `services/api/config.ts`, parser des 4 codes, `LoginScreen.handleForbidden` mappe sur l'UI (BLOCKED → support, UNVERIFIED → CTA renvoyer email, PENDING_VALIDATION → info attente, UNAUTHORIZED → refus simple). Le 429 ne pollue plus le compteur lockout local.
- **Web** : `utils/authErrors.ts` table `FORBIDDEN_UI` (source unique des libellés/CTA), `app/login/page.tsx` UI différenciée par code (UNVERIFIED → modal verify, BLOCKED → toast persistant, PENDING_VALIDATION → toast info, UNAUTHORIZED → setError).

#### 2.3.4 Mutex refresh token web
- `src/api/refreshManager.ts` (singleton mutex inspiré du `refreshManager` mobile existant) : promise mémorisée **avant tout `await`** (ferme la race window) + anti-rebond 5s. `tokenRefresh.ts` délègue le verrou (21/21 tests passent).

#### 2.3.5 Endpoint `POST /api/v1/admin/users/:id/quota`
- Backend : `setUserQuotaBytes` (body `{ quotaBytes }` — number, pas GB) → `{ id, quotaBytes }`. Validation : type, finite, ≥ 0, max 1 Po. PATCH `/quota` legacy (`{ quotaGb }`) gardé pour rétro-compat.

## 5. 📐 Recommandation stratégique

### Option A — Monorepo + package `@qvarry/contracts` (recommandé)
- Restructurer en monorepo (Turborepo / Nx / pnpm workspaces)
- Package `contracts` qui exporte : types modèles, enums partagés, schémas Zod, liste des routes typées
- Backend, mobile, web l'importent → toute désync = erreur TS
- Effort one-shot ~1 semaine, gains permanents

### Option B — OpenAPI + codegen
- Générer spec OpenAPI depuis le backend (express-openapi-validator ou Zod-to-OpenAPI)
- Codegen des clients TypeScript pour mobile et web
- Pas de monorepo nécessaire mais codegen à maintenir

### Option C — Contract testing (Pact)
- Tests d'intégration en CI qui valident les contrats
- Détecte les drifts mais ne les empêche pas en local
- À combiner avec A ou B, pas seul

**Recommandation finale** : **Option A**. Monorepo apporte aussi des bénéfices secondaires (CI mutualisée, refacto cross-projet plus simples, partage helpers comme validation password déjà factorisable).
