## 3. P0 — URGENT (bugs runtime ou risques critiques avérés)

### 3.1 — Messagerie web temps-réel cassée (cross-repo drift WS)

**Vérifié runtime** :
- Backend émet (snake_case) : `messages`, `message_read`, `message_reply`, `message_edited`, `message_deleted` (`src/services/webSocketService.ts:2389/2413/2441/2461/2477`).
- Web écoute (camelCase) : `messagesList`, `messageRead`, `messageSent`, `messageEdited`, `messageDeleted` (`src/utils/useWebSocketMessages.ts:217-242`).

**Impact** : la messagerie web ne reçoit **aucun update temps-réel** — read receipts, édition, suppression, historique listing tous silencieusement perdus. L'utilisateur web doit refresh la page pour voir les nouveaux messages. Mobile (`MessageWebSocketService` + `useMessages.ts`) utilise le bon snake_case → bug **uniquement web**.

**Effort fix** : 30 min. Renommer les 5 events côté web pour matcher backend.

### 3.2 — Enum `ACCES_SOUTERRAIN` web diverge du backend (fiches partiellement cassées)

**Vérifié runtime** :
- Backend `FICHE_ACCES_SOUTERRAIN` = `["Porte", "Chatière", "Escalade", "Ouvert", "Autre"]` (5 valeurs, `fichesEnums.ts:33`).
- Web `ACCES_SOUTERRAIN` = `["Porte", "Chatière", "Puits", "Trappe", "Escalier", "Passage voûté", "Autre"]` (7 valeurs, `constants/fiches.ts:73-81`).

**Impact** : tout PATCH/POST fiche depuis web avec `Puits / Trappe / Escalier / Passage voûté` est rejeté 400 par `z.enum(FICHE_ACCES_SOUTERRAIN)` Zod (V8.5). **Création/édition fiche web cassée pour ces 4 valeurs**. Mobile aligné (`constants/fiches.ts:19`).

**Effort fix** : 15 min. Aligner web sur backend (supprimer 4 valeurs web ou ajouter 2 valeurs backend selon décision produit).

### 3.3 — Backend émet `sos_participant_removed`, aucun client ne l'écoute

**Confirmé** : déjà signalé V8.4 puis V8.5 mais non fixé. Backend `sosService.ts:4319,4826`. Mobile `SosContext.tsx` ne case que `sos_participant_added/_left/...`. Web : 0 occurrence.

**Impact** : quand un admin retire un user d'une session SOS de groupe, son client garde `participants[]` et `activeSession` figés → notification fantôme, refus de redéclencher SOS, possible heartbeat sur session terminée backend. **Régression SOS — safety-critical**.

**Effort fix** : 1-2h. Ajouter handler `sos_participant_removed` côté mobile + web qui retire le user de `participants[]` et résout `activeSession` si `targetUserId === currentUserId`.

### 3.4 — Backup MongoDB & disaster recovery procedure manquants

**Confirmé** : aucun script de backup automatisé dans le repo backend. Aucun RTO/RPO documenté. Aucune procédure de restauration testée.

**Impact** : perte totale de données si MongoDB Atlas corrupt ou compte compromis. Incident P0 sans possibilité de rollback.

**Effort fix** : 1j. Documenter procédure backup Atlas (snapshots automatiques + restauration testée). Si Atlas pas suffisant, scripts `mongodump` daily + S3 retention 30j.

### 3.5 — Webhook Vonage rate-limit par IP uniquement (DoS possible)

**Confirmé** : `webhookRoutes.ts:25-34` rate-limit 100/min par IP. Vonage utilise ses propres IPs, un attaquant n'a pas besoin d'attacher différentes IPs pour saturer (le webhook est protégé HMAC ✅ mais le rate-limit ne défend pas l'endpoint en cas de bombardement de signatures valides volées).

**Impact** : risque DoS modéré. Hash collision sur (msisdn, messageId) limitée.

**Effort fix** : 1h. Rate-limiter par hash(messageId) ou (to, msisdn).

### 3.6 — Distributed tracing & Sentry mobile absents

**Confirmé** :
- Pas d'OpenTelemetry / Jaeger / Datadog APM côté backend.
- Pas de Sentry / Bugsnag / Crashlytics côté mobile RN. Web : Sentry installé `app/error.tsx` + `app/global-error.tsx`.

**Impact** :
- En cas de latence client→backend→DB, impossible de retracer cross-layer.
- Crashes mobile en prod invisibles (discovery via support user 24h+).

**Effort fix** : Sentry mobile = 1-2h (installation + DSN env). OpenTelemetry backend = 1-2j (config exporter + instrumentation manuelle des routes critiques).

## 4. P1 — IMPORTANT (UX cassée, data integrity, risques modérés)

### 4.1 — Sécurité backend

- **CSRF rotation pas obligatoire post-réponse** (`src/middlewares/csrfMiddleware.ts:268-298`). Token valide 1h peut être rejoué. Action : activer rotation sur routes mutantes sensibles ou documenter le choix.
- **2FA recovery codes — risque replay en session** (`twoFactorControllers.ts:388-412`). Splice array sans `usedAt` timestamp ou Redis set atomique. Refetch DB avant save peut permettre double-usage. Action : marquer atomique en Redis avec TTL 24h.
- **Rate limit `mobileAttestationByDeviceLimiter` sans canonicalisation deviceId** (`rateLimitConfig.ts:569-577`). Bypass via `" devA"` vs `"devA"`. Action : `deviceId.trim().toLowerCase()` avant hash.
- **Audit logs potentiel DoS sur audit collection** (`auditService.log()` appelé sans batch sur certains rate-limit handlers). Action : confirmer Mongo absorbe + batching si nécessaire.

### 4.2 — Sécurité clients

- **Mobile `decodeJWTForUI` sans vérification signature** (`tokenStore.ts:19-29`). Extraction `jti` base64 only pour filtrer WS `session_revoked`. Backend valide avant broadcast, mais ajoute surface d'attaque si WS forgé.
- **Mobile `secureTokenStore.setAccessToken()` fire-and-forget** (`tokenStore.ts:49-52`). Crash app avant `.catch()` → in-memory token mais secure store vide au restart.
- **Web `sessionStorage qvarry_session_token_id` unencrypted**. Non-sensitive (déjà dans JWT) mais XSS peut craft `session_revoked`. Action : in-memory store si possible.
- **Mobile WebView CSP `'unsafe-inline'` scripts + styles** (`webviewSecurity.ts:71-74,89-93`). Leaflet exige inline. Sanitization en place mais widens XSS surface.
- **Web build `.next` artifacts** — vérifier `productionBrowserSourceMaps: false` + `.map` exclus du deploy prod.
- **Mobile deep link params non validés explicitement** (`App.tsx:68-107`). `linking.prefixes` whitelist OK mais pas de runtime validation des `params` (path traversal théorique).
- **Web open redirect (à vérifier)** sur `/share`, `/accept`, `/decline` — confirmer validation server-side des params `token`/`id` avant 30x.

### 4.3 — Cross-repo consistency

- **Mobile `useConversations.ts:425` écoute `conversation_preferences_updated` — 0 émission backend** (handler dead code, UX désynchro multi-device).
- **Mobile `useConversations.ts:442` écoute `conversation_read` — 0 émission backend** (avec `as any` masquant le bug TS).
- **Mobile types Fiche enums divergent en NOM mais pas en VALEURS** (`Qvarry-phone/src/types/fiche.ts:6-18` : `FicheDifficulte` vs backend `FicheDifficulteAcces`). Pas de bug runtime mais zéro typecheck cross-repo.
- **Web sans companion fields `acces_souterrain_autre / equipement_autre / praticite_autre`** présents côté mobile + backend. Si user web sélectionne "Autre", aucun input texte associé posté → champs orphelins.

### 4.4 — Production-readiness

- **Sentry mobile absent** (cf. §3.6).
- **Error boundaries React web incomplets**. `error.tsx` + `global-error.tsx` ✅ mais aucun `<ErrorBoundary>` dans modales (CreatePointModal, FicheViewModal) ni Dashboard. Erreurs UI silencieuses.
- **Feature flags absents** (zéro LaunchDarkly / homemade). Kill switch sur route cassée = redeploy 30 min vs flag 30s.
- **Pool Mongo monitoring absent**. `maxPoolSize: 50` en prod, aucune métrique sur saturation.
- **Migration idempotence non testée** (`addPhotoStorageFields.ts` + `generateUserKeys.ts` jamais invoquées au boot). Re-deploy sur DB old peut échouer silencieusement.

### 4.5 — Dette technique

- **Divergence règles password validators cross-repo** : backend = 12 chars + spécial (`passwordUtils.ts:13`), mobile login = 8 chars sans spécial (`utils/validation.ts:62`), mobile register = 12 chars mais regex différente (`validation.ts:84`), web = 12 + spécial (`utils/validation.ts:79`). Faux positifs / faux négatifs UX possibles.
- **Routes legacy mobile vraiment orphelines** : `/mobile/auth/login-legacy` (`mobileAuthRoutes.ts:198`) + `/mobile/auth/verify-login-legacy` (`mobileTwoFactorRoutes.ts:291`). 0 call client. Effort suppression 30 min.
- **10 fichiers stubs admin orphelins** mobile (`screens/admin/security/*.tsx` + `screens/admin/sos/*.tsx` + `screens/admin/storage/*.tsx`). Tous "TODO Implémenter", remplacés par `ComingSoonScreen`. Effort 5 min `git rm`.
- **`api.generated.ts` (V6 N1) posée mais zéro consumer**. SSOT type dormante. Décision : adopter progressivement ou retirer pour ne pas confondre.
- **Dépendances npm non utilisées** : `mongodb`, `mime-types` (backend) ; `@radix-ui/react-popover`, `leaflet.awesome-markers` (web).
